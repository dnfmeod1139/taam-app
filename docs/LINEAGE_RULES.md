# 계보도 (Lineage SVG) 글로벌 룰

> 2026-05-22 — 사용자가 정한 **1순위 규칙**.
> **모든 계보도 (스기타·카네사카·큐베이·사이토·우미·지로·아라이·쇼·뉴9·뉴10·뉴11·뉴12) 에 동일 적용.**
> 새 계보도를 추가할 때도 이 문서 기준으로 작업.

---

## 🥇 1순위 — 파이프라인이 노드/이름을 절대 침범하지 않는다 + 박스 면 중앙으로만 진입/이탈

**가장 중요한 규칙. 절대 어겨선 안 됨.**

### A. 침범 금지
- 파이프라인(path)은 노드 박스 영역(rect/image)을 **가로지르지 않는다**.
- 파이프라인은 노드의 **매장 이름 텍스트 / 쉐프 이름 텍스트** 영역을 가로지르지 않는다.

### B. 박스 4면 정중앙 규칙 ⭐
**path 의 시작점·끝점은 항상 노드의 4면 중앙 중 하나** — 박스 안으로 절대 들어가지 않는다.

자식 노드 진입점 (박스 4면 중앙):
- 상단 중앙: `(cx, cy - 29)`
- 하단 중앙: `(cx, cy + 29)`
- 좌측 중앙: `(cx - 29, cy)`
- 우측 중앙: `(cx + 29, cy)`

부모 노드 출발점 (박스 + 이름 영역 외곽 중앙):
- 상단 중앙: `(cx, cy - 29)`
- **하단 중앙: `(cx, cy + 62)`** (이름 영역 끝 — 이름 침범 방지)
- 좌측 중앙: `(cx - 29, cy)`
- 우측 중앙: `(cx + 29, cy)`

### C. 노드 위치 / 추가 시 자동 유지
- 노드 위치 변경 시 — **path 의 끝점·중간 꺾임도 함께 재계산**해서 위 규칙 유지.
- 노드 추가 시에도 새 path 가 기존 노드/이름을 가로지르지 않도록 ㄱ자/ㄴ자 경로 사용.
- `calcCustomConnectionPath` 의 `_decideAnchors()` 가 자동으로 진입 방향 결정 (수직/수평).

### 자주 침범하는 케이스 (방어)
| 케이스 | 해결 |
|---|---|
| 가운데 트렁크(x=190 류)가 좌측 노드(x<190) 의 이름 텍스트 영역을 가로지름 | 노드 위치를 가운데 트렁크에서 멀리 두거나, 트렁크 우회 |
| 가로 분기 path 가 다른 노드의 박스를 통과 | 분기 path 의 y 를 노드 박스 위/아래로 옮기거나, 부모 path 자체 위치 조정 |
| 위로 가는 path (자식 → 부모) 끝점이 부모 박스 위 30px 이내 — 이름 영역에 박힘 | 끝점을 박스 가장자리(cx, cy-29)로 |

## 🥈 2순위 — 애니메이션 순서: 화면 상단 → 하단 (y 오름차순)

**부모 라인이 노드보다 미리 화면 끝까지 그어지지 않는다.**
**시간순(연도순) 정렬은 무시. 화면 위 → 아래 순서가 우선.**

각 단계(stage)는 다음 순서로:
1. 노드가 등장할 **세로 위치 (cy)** 까지 가운데 트렁크(부모 라인) 연장
2. 그 노드로 가는 **분기 파이프라인** 등장
3. **노드** 등장 (박스 + 사진 + 이름)
4. (다음 노드를 위해 1번부터 반복)

구현 패턴 (카네사카 기준 — 다른 계보에도 동일 적용):
- `setTrunkProgress*(targetY, duration)` — 트렁크를 targetY 까지 단계적 연장
- `NODE_Y_*` 매핑 — 노드 id → cy 좌표
- `showEl*(id)` 호출 시 자동으로 `setTrunkProgress*` 발동 (내장)
- `startAnim*` 함수는 **stages 배열 기반** — y 오름차순으로 정렬

같은 y 좌표의 노드들은 같은 stage 에서 동시 등장 (예: 카네사카 마모루+이시야마 둘 다 y=700).

## 🥉 3순위 — 파이프라인 색상 검정 통일

- **모든 파이프라인 `<path>` stroke = `#1a1a18`** (검정)
- 한국 진출 / 해외 / 제자 등의 강조는 **노드 테두리 (rect stroke) / 연도 배지** 로만 표시
- path 색상으로 강조 X
- 두께: 트렁크 `2.5px`, 분기 path `1.8~2px`, 약한 관계 `1.2~1.5px`

(점선 `stroke-dasharray` 는 사용 가능 — 의미상 약한 관계/추정 라인)

## 5순위 — 동적 노드 (사용자가 추가한 노드)

- 모든 계보에서 슈퍼어드민이 **`addNodeModal`** 로 노드 추가 가능
- 좌표·이름·부제·테두리 색상·부모 노드 지정
- 부모 노드 선택 시 **하드코딩 + 다른 동적 노드** 모두 후보로 표시 (🆕 마크로 구분)
- 추가 시 자동으로 정보 페이지 + 편집 모드 진입 → sec1 / sec2 / 사진 입력
- **Supabase `chefs.geometry` 컬럼**에 좌표/부모 정보 저장 → 모든 기기 동기화
- IDB 백업 (오프라인 대비)

## 노드 좌표 변경 / 노드 추가 시 체크리스트

- [ ] 새 좌표가 **다른 노드 박스 영역 (cx±29, cy±29)** 과 충돌하지 않는다
- [ ] 부모 라인(path d) 끝점이 **노드 박스 가장자리** 에 닿는다 (이름 텍스트 영역 X)
- [ ] 자식 라인(path d) 시작점이 **부모 노드 박스 아래 또는 이름 영역 아래** 에서 시작
- [ ] 가로 path 가 **다른 노드를 가로지르지 않는다**
- [ ] path 색상 `#1a1a18` (검정 통일)
- [ ] `PIPES_*` 길이 갱신 — `getTotalLength` 계산값 또는 Manhattan distance
- [ ] `NODE_Y_*` 매핑에 새 노드 cy 등록 (애니메이션 진행용)
- [ ] 동적 노드인 경우 `chefs.geometry` 에 좌표·부모 정보 저장 (Supabase 동기화)
- [ ] 글씨 크기·폰트·색상 → 4순위 표 준수

## 새 계보도 추가 시 가이드

1. SVG 파일 구조: 부모 트렁크 + 분기 path + 노드 g 그룹들
2. **path stroke 모두 `#1a1a18`** (1순위 룰 + 3순위 룰)
3. `NODE_Y_<XX>` 매핑 정의 + `PIPES_<XX>` 길이 매핑
4. `setTrunkProgress<XX>(targetY, dur)` 함수 정의
5. `showEl<XX>(id, delay, cb)` 함수 내부에 `NODE_Y_<XX>[id]` 참조 → 자동 트렁크 진행
6. `startAnim<XX>()` 는 **stages 배열 기반** — y 오름차순
7. 글씨 크기 → `CUSTOM_FONT_MAP[<XX>] = { name, sub }`
8. 동적 노드 prefix 등록 (`renderCustomNodes` 가 자동 처리)
